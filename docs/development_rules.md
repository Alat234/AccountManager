# Правила розробки від користувача

1. Перед практичною реалізацією прочитати відповідні документи в `docs` та
   скласти план: взаємодії користувача, основний сценарій, альтернативні шляхи,
   помилки, скасування, повторний запуск і непередбачувані стани.
2. Не перевантажувати класи, функції та файли. Розділяти відповідальності,
   проєктувати код для розширення та підтримки повноцінного продукту.
3. Ключові продуктові рішення узгоджувати з користувачем, якщо він ще не дав
   точних вказівок. Не запитувати повторно вже визначені рішення.
4. Актуальні вказівки користувача мають пріоритет над старими сценаріями в docs.
